### Definition

YAGNI (You Ain’t Gonna Need It) is a software development principle that suggests that developers should not add functionality to a codebase unless it is immediately necessary. The idea is to avoid creating unnecessary complexity in the codebase by only adding features that are actually needed.

The YAGNI principle is closely related to the Single Responsibility Principle (SRP) and the Open-Closed Principle (OCP), which are part of the SOLID principles. YAGNI aims to keep the codebase as simple as possible by avoiding the creation of unnecessary abstractions and functionality.

### Origin and purpose

YAGNI ("you aren't gonna need it") is a practice from extreme programming (XP) which states that features should only be added when they are required. It trims excess and inefficiency from development so that releases can be more frequent.

The principle helps developers avoid wasted effort on features that are assumed to be needed at some point. That assumption often turns out to be wrong. Even if the feature is wanted later, the implementation built in advance may not be the one that is needed. Because no time goes into features that may never be used, the main features get more attention and each release takes less time. Like the "worse is better" philosophy, YAGNI argues against extra features and helps avoid [feature creep](../../../software-requirements/management-activities/feature-creep.md). It is usually mentioned together with [KISS](kiss.md) and [DRY](dry.md).
