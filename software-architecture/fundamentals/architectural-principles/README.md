# Architectural principles

Principles that guide how components, boundaries and dependencies are arranged so that an architecture stays easy to change.

This section corresponds to topic 2.1 of the [SWEBOK Guide V4.0](https://www.computer.org/education/bodies-of-knowledge/software-engineering).

## Overview

Architectural principles refer to a set of guidelines or rules that are used to guide the design and development of a software architecture. These principles are intended to ensure that the resulting architecture is maintainable, scalable, and easy to understand and modify. Some common architectural principles include the separation of concerns, modularity, loose coupling, and high cohesion. Additionally, architectural principles are often used in conjunction with design patterns, which are reusable solutions to common software design problems.

## Reading order

1. [Component principles](component-principles.md): Component principles guide which classes belong together in a component and how components may depend on each other.
2. [Policy and detail](policy-and-detail.md): Policy is the business rules and high level decisions of a system; details are the mechanisms such as databases, frameworks, user interfaces and devices.
3. [Architectural boundaries](boundaries.md): Architectural boundaries are the lines that separate components, layers or services, and that control which dependencies may cross them.
